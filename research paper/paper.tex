\begin{abstract}
UAV swarm networks require lightweight, fast, and secure authentication protocols for real-time operations such as formation flying and aerial surveillance. Traditional PKI approaches (RSA-2048, ECC-256) incur 8--15\,ms latencies on embedded processors and require secure key storage---a liability when UAVs are physically captured. We present a four-phase Physical Unclonable Function (PUF)-based authentication protocol: (1)~secure enrollment with BCH fuzzy extractors, (2)~UAV--Ground Station mutual authentication via PUF challenge-response, (3)~direct peer-to-peer UAV authentication without Ground Station involvement, and (4)~session key establishment. We evaluate the protocol in OMNeT++ 6.3 using a 10-UAV stadium surveillance scenario with SHA3-256 and SPONGENT-160 hash modes. Results show Phase~2 latency of 0.672\,ms (SHA3) / 7.368\,ms (SPONGENT), Phase~3 latency of 0.476\,ms (SHA3) / 14.535\,ms (SPONGENT), with 100\% success across all 10 UAV--GS and 45 peer pairs. The protocol is 10--22$\times$ faster than RSA/ECC with only 430 bytes total overhead. All results were obtained on an x86-64 laptop; hardware FPGA/ASIC projections are provided.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Unmanned Aerial Vehicle (UAV) swarms are increasingly deployed for surveillance, disaster response, precision agriculture, and border patrol. Multi-UAV coordination demands mutual authentication---each UAV must verify the identity of its Ground Station (GS) and peer UAVs before accepting commands, sharing sensor data, or coordinating flight paths. Without robust authentication, adversaries could inject rogue UAVs, intercept surveillance data, or perform man-in-the-middle attacks on inter-UAV communications~\cite{securing_uav_fanet}.

The authentication challenge is particularly acute in UAV swarms because of stringent timing requirements (sub-millisecond for formation flying at 10--50\,Hz update rates), limited computational resources (ARM Cortex-M4/M7 processors), constrained wireless bandwidth (shared 802.11 channels), and the physical vulnerability of UAVs to capture in hostile environments~\cite{puf_uav_cross_domain}.

Traditional approaches face critical limitations: RSA-2048 digital signatures require 8--15\,ms per verification on ARM Cortex-A72 processors---for a 10-UAV swarm, full-mesh mutual authentication would take 720--1350\,ms, far exceeding real-time requirements. ECC-256 reduces this to 4--8\,ms per operation but still requires secure storage of private keys; physical capture of a UAV enables key extraction via side-channel attacks or direct memory probing~\cite{puf_lightweight_uav}. Pre-Shared Key (PSK) schemes achieve sub-millisecond latency but expose the fleet if any single UAV is captured, and key management complexity scales as $O(N^2)$~\cite{peer2peer_auth}. Blockchain-based authentication incurs consensus latency of 1--10 seconds, making it impractical for real-time operations~\cite{puf_iot_strong_adversary}.

Physical Unclonable Functions (PUFs) address these fundamental limitations by exploiting intrinsic, random manufacturing variations in integrated circuits to generate unique challenge-response pairs (CRPs). PUFs provide: (1)~\emph{unclonability}---sub-nanometer variations cannot be replicated; (2)~\emph{unpredictability}---responses to new challenges cannot be predicted; (3)~\emph{no key storage}---the ``key'' is the silicon itself; (4)~\emph{tamper evidence}---physical probing destroys the PUF. An Arbiter PUF circuit requires as few as 1,200 gate equivalents (GE)~\cite{puf_overview, arbiter_puf_iot}.

\textbf{Contributions.} We present:
\begin{enumerate}[leftmargin=*,nosep]
    \item A complete four-phase PUF protocol covering enrollment, UAV--GS mutual authentication, direct peer-to-peer authentication (without GS), and session key establishment.
    \item Full-mesh peer authentication ($N(N{-}1)/2 = 45$ pairs for 10 UAVs).
    \item Dual hash mode evaluation: SHA3-256 (software-optimized) and SPONGENT-160 (hardware-optimized, 2,190 GE).
    \item Validated OMNeT++ 6.3 implementation with per-message timing breakdowns.
    \item Comprehensive comparison against RSA, ECC, PSK, and existing PUF protocols.
\end{enumerate}

\section{Background}
\label{sec:background}

A Physical Unclonable Function (PUF) maps challenges to responses via intrinsic manufacturing variations: $R = \text{PUF}(C)$, providing \emph{unclonability}, \emph{unpredictability}, and \emph{tamper evidence}~\cite{puf_overview}. We use a 128-stage Arbiter PUF ($\sim$1,200~GE, exponential CRP space $2^n$, 3\% BER)~\cite{arbiter_puf_iot}. Ring Oscillator PUFs offer lower noise but limited CRP space~\cite{ro_puf_design}; SRAM PUFs require no extra hardware but have limited challenge space~\cite{sram_puf_bch}.

We evaluate two hash functions: \textbf{SHA3-256} (Keccak~\cite{sha3_standard}, 1600-bit state, $\sim$0.4\,$\mu$s/call on x86-64 via OpenSSL, truncated to 160~bits) and \textbf{SPONGENT-160} (176-bit state, 80 rounds, 2,190~GE~\cite{spongent_original}, $\sim$890\,$\mu$s/call in software---a 2,225$\times$ gap that collapses to 2--5$\times$ on FPGA/ASIC). PUF noise is corrected by a fuzzy extractor using BCH(255,~131,~18): helper data $h = \text{BCH\_enc}(R) \oplus R$ enables correction of up to 18~bit errors (14\% BER), well above the 3\% expected BER~\cite{bch_puf_extraction}.

\section{Related Work}
\label{sec:related}

Gope and Sikdar~\cite{puf_lightweight_uav} propose PUF-based UAV--GS authentication (10--50\,ms, Raspberry~Pi) but lack peer-to-peer capability. Li~\emph{et~al.}~\cite{puf_uav_cross_domain} address cross-domain UAV PUF authentication (45--80\,ms); Khan~\emph{et~al.}~\cite{puf_6g_uav} target 6G UAV networks (5--20\,ms). Neither provides direct UAV-to-UAV authentication, dual hash evaluation, or full-mesh analysis. Bera~\emph{et~al.}~\cite{peer2peer_auth} achieve sub-ms peer authentication using PSK but require stored keys vulnerable to physical capture. Our protocol uniquely combines PUF hardware root-of-trust with both UAV--GS and direct peer-to-peer authentication.

\subsection{Threat Model}
We adopt the Dolev-Yao model augmented with physical capture: the adversary can eavesdrop, intercept, modify, replay, or drop wireless messages; may capture UAVs and read NVM but cannot clone PUFs; and is computationally bounded (PPT)~\cite{dolev_yao}.

\subsection{Phase~1: Secure Enrollment}
Enrollment occurs once in a secure facility with tamper-proof channels. For each UAV$_i$:

\textbf{Step~1.1 (PUF Interrogation):} GS generates $n \geq 12$ random 128-bit challenges $\{C_i^{(1)}, \ldots, C_i^{(n)}\}$ and collects responses:
\begin{equation}
R_i^{(k)} = \text{PUF}_i(C_i^{(k)}), \quad k = 1, \ldots, n
\label{eq:puf_eval}
\end{equation}

\textbf{Step~1.2 (Error Correction Setup):} For each CRP, helper data is computed:
\begin{equation}
h_i^{(k)} = \text{BCH\_encode}(R_i^{(k)}) \oplus R_i^{(k)}
\label{eq:helper}
\end{equation}
This public data enables reliable PUF reconstruction without revealing $R_i^{(k)}$.

\textbf{Step~1.3 (Identity \& Credential Generation):} GS assigns:
\begin{align}
\text{TID}_i &= h(\text{ID}_i \| \text{seed}_i) \label{eq:tid}\\
\tau_i &= h(R_i^{(1)} \| \text{ID}_i \| T_{\text{reg}}) \label{eq:token}
\end{align}
and pre-computes peer secrets for all pairs:
\begin{align}
P_{ij} &= h(R_i^{(1)} \| \text{ID}_j \| N_{\text{gs}}) \label{eq:peer_secret}\\
\text{Mask}_{ij} &= P_{ij} \oplus P_{ji} \label{eq:mask}
\end{align}

\textbf{Step~1.4 (Storage):} GS stores $\{$ID$_i$, TID$_i$, $\{(C_i^{(k)}, h_i^{(k)})\}_{k=1}^{n}\}$. UAV stores only $\sim$50~bytes (\text{TID}$_i$, $\tau_i$, GS parameters). No PUF responses or private keys are retained on the UAV.

\subsection{Phase~2: UAV--GS Mutual Authentication}
A four-message protocol executed when a UAV enters the operational field. The full exchange is shown in Fig.~\ref{fig:phase2}.

\textbf{Message~1 (Auth Request):} UAV$_i \to$ GS:
\begin{align}
\alpha_1 &= h(\text{TID}_i \| T_1 \| N_1 \| \tau_i) \label{eq:m1_mac}\\
M_1 &= \langle \text{TID}_i,\; T_1,\; N_1,\; \alpha_1 \rangle \label{eq:m1}
\end{align}
Format: $64 + 32 + 128 + 160 = 384$~bits (48~bytes). The MAC $\alpha_1$ binds the request to the UAV's registration token $\tau_i$, which only a legitimately enrolled UAV possesses.

\textbf{Message~2 (Challenge):} GS $\to$ UAV$_i$. GS verifies $\alpha_1$ using its database, selects an unused CRP $(C_i^{(k)}, h_i^{(k)})$, and responds:
\begin{align}
\beta_1 &= h(C_i^{(k)} \| N_1 \| N_2 \| T_1) \label{eq:m2_mac}\\
M_2 &= \langle C_i^{(k)},\; N_2,\; \beta_1,\; h_i^{(k)},\; T_2 \rangle \label{eq:m2}
\end{align}
Format: $128 + 128 + 160 + 255 + 32 = 703$~bits ($\approx$88~bytes). The MAC $\beta_1$ authenticates the GS to the UAV.

\textbf{Message~3 (PUF Response):} UAV$_i \to$ GS. The UAV evaluates its PUF and performs BCH correction:
\begin{align}
R_i^{\text{noisy}} &= \text{PUF}_i(C_i^{(k)}) \\
R_i &= \text{BCH\_correct}(R_i^{\text{noisy}},\; h_i^{(k)}) \\
R_i^{\text{masked}} &= R_i \oplus h(N_2) \label{eq:mask_resp}\\
\gamma_1 &= h(R_i \| N_1 \| N_2 \| T_2) \label{eq:m3_mac}\\
M_3 &= \langle R_i^{\text{masked}},\; \gamma_1,\; T_3 \rangle \label{eq:m3}
\end{align}
Format: $128 + 160 + 32 = 320$~bits (40~bytes). The PUF response is masked by $h(N_2)$ to prevent eavesdropping.

\textbf{Message~4 (Confirmation):} GS $\to$ UAV$_i$. GS unmasks the response, verifies via Hamming distance, derives a session key, encrypts peer credentials, and rotates the TID:
\begin{align}
\text{SK}_{i,\text{GS}} &= h(R_i \| N_1 \| N_2) \label{eq:sk_gs}\\
\delta_1 &= h(\text{SK}_{i,\text{GS}} \| \text{Cred}_i^{\text{enc}} \| T_4) \label{eq:m4_mac}\\
M_4 &= \langle \text{Cred}_i^{\text{enc}},\; \delta_1,\; \text{TID}_i^{\text{new}},\; T_4 \rangle \label{eq:m4}
\end{align}
Total Phase~2: \textbf{175~bytes} across 4 messages. The CRP is marked consumed, preventing replay.

\subsection{Phase~3: Peer-to-Peer Authentication}
A three-message protocol enabling direct mutual authentication between UAV pairs using Phase~2 credentials, requiring \emph{no GS involvement} during flight (Fig.~\ref{fig:phase3}).

\textbf{Message~P1 (Peer Auth Request):} UAV$_i \to$ UAV$_j$:
\begin{align}
\eta_1 &= h(\text{TID}_i \| \text{TID}_j \| n_i \| T_{p1}) \label{eq:p1_mac}\\
P_1 &= \langle \text{TID}_i,\; C_j,\; n_i,\; \eta_1,\; T_{p1} \rangle \label{eq:p1}
\end{align}
Format: $64 + 128 + 160 + 160 + 32 = 544$~bits (68~bytes).

\textbf{Message~P2 (Challenge Response):} UAV$_j \to$ UAV$_i$. The responder derives the initiator's peer secret, constructs an encrypted authentication puzzle, and responds:
\begin{align}
P_{ji} &= h(R_j \| \text{ID}_i \| N_{\text{gs}}) \label{eq:p2_secret}\\
\tilde{P}_{ij} &= \text{Mask}_{ij} \oplus P_{ji} \label{eq:p2_recover}\\
Q_i &= E_{\tilde{P}_{ij}}(n_j \| C_i \| T_{p1}) \label{eq:puzzle}\\
\eta_2 &= h(Q_i \| n_i \| T_{p2}) \label{eq:p2_mac}\\
P_2 &= \langle Q_i,\; \eta_2,\; T_{p2} \rangle \label{eq:p2}
\end{align}
Format: $320 + 160 + 32 = 512$~bits (64~bytes). The XOR mask $\text{Mask}_{ij} = P_{ij} \oplus P_{ji}$ acts as an information-theoretically secure one-time pad.

\textbf{Message~P3 (Mutual Completion):} UAV$_i \to$ UAV$_j$. The initiator decrypts $Q_i$ using its own $\tilde{P}_{ij}$, verifies nonces and timestamps, then constructs a reciprocal puzzle:
\begin{align}
Q_j &= E_{\tilde{P}_{ji}}(n_i' \| T_{p2}) \label{eq:puzzle_j}\\
\eta_3 &= h(Q_j \| n_j \| T_{p3}) \label{eq:p3_mac}\\
P_3 &= \langle Q_j,\; \eta_3,\; T_{p3} \rangle \label{eq:p3}
\end{align}
Total Phase~3: \textbf{104~bytes} across 3 messages in OMNeT++ (theoretical: 196~bytes with full credential packaging). For $N$ UAVs, full-mesh authentication requires $N(N{-}1)/2$ pairs (45 for $N$=10).

\subsection{Phase~4: Session Key Establishment}
After successful Phase~3 completion, both UAVs derive a shared symmetric session key:
\begin{equation}
\text{SK}_{ij} = h(n_i \| n_j \| n_i' \| R_i \| R_j)
\label{eq:sk}
\end{equation}
\textbf{Properties:} 160-bit key strength; freshness from ephemeral nonces $n_i, n_j, n_i'$; mutual contribution (both parties contribute randomness); PUF binding (requires $R_i, R_j$ that only authentic hardware can produce); unique per session. For \emph{perfect forward secrecy} (PFS), an optional ECDH extension is available:
\begin{equation}
\text{SK}_{ij}^{\text{PFS}} = h(n_i \| n_j \| n_i' \| R_i \| R_j \| g^{a_i b_j})
\label{eq:sk_pfs}
\end{equation}
where $a_i, b_j$ are ephemeral Diffie-Hellman exponents. Even if PUF responses $R_i, R_j$ are later compromised, past session keys remain secure due to the ephemeral DH contribution.

The architecture comprises three OMNeT++ modules: \textbf{UAVNode} (Phase~2 client, Phase~3 initiator/responder, PUF simulator, HashWrapper), \textbf{GroundStation} (enrollment database, BCH decoder, credential distribution), and \textbf{NetworkController} (lifecycle management).

Communication uses \texttt{sendDirect()} with delay model: $d_{\text{total}} = d_{\text{prop}} + d_{\text{serial}} + d_{\text{proc}} + d_{\text{jitter}}$. Each UAV initiates Phase~3 with all higher-ID peers (45 unique pairs), staggered to avoid overlap.

\textbf{Important:} All cryptographic operations execute as native C++ on an x86-64 laptop. Absolute timings differ from real UAV hardware (ARM: 10--100$\times$ slower; FPGA/ASIC: 100--1000$\times$ faster for SPONGENT). \emph{Relative} comparisons remain valid.

\section{Security Analysis}
\label{sec:security_analysis}

\begin{theorem}[Phase~2 Mutual Authentication]
\label{thm:mutual}
After Phase~2, both UAV$_i$ and GS are mutually authenticated.
\end{theorem}
\emph{Proof:} (1)~GS authenticates UAV$_i$ via $\gamma_1 = h(R_i \| N_1 \| N_2 \| T_2)$---forging $\gamma_1$ requires $R_i = \text{PUF}_i(C_i)$, obtainable only from the authentic PUF (unclonability). (2)~UAV$_i$ authenticates GS via $\beta_1 = h(C_i \| N_1 \| N_2 \| T_1)$---forging requires the CRP database stored exclusively at GS. (3)~An adversary cannot predict $R_i$ from $C_i$ without physical access (unpredictability). \hfill$\square$

\begin{theorem}[Replay Attack Resistance]
\label{thm:replay}
The protocol prevents replay attacks in all phases.
\end{theorem}
\emph{Proof:} (1)~Fresh timestamps $T_1, T_2, T_3, T_4$ in all messages; messages with $|T_{\text{current}} - T_i| > \Delta T_{\max}$ are rejected. (2)~Fresh random nonces $N_1, N_2$ ensure message uniqueness across sessions. (3)~CRPs are marked ``consumed'' after use---replaying $M_3$ with a previously used $(C_i, R_i)$ pair fails GS verification. (4)~Phase~3 nonces $n_i, n_j$ are ephemeral and bound into MACs $\eta_1, \eta_2, \eta_3$. \hfill$\square$

\begin{theorem}[Peer Mutual Authentication]
\label{thm:peer}
Phase~3 provides mutual authentication between UAV$_i$ and UAV$_j$ without GS involvement.
\end{theorem}
\emph{Proof:} (1)~UAV$_j$ is authenticated by UAV$_i$ because decrypting puzzle $Q_i = E_{\tilde{P}_{ij}}(n_j \| C_i \| T_{p1})$ requires knowledge of $\tilde{P}_{ij}$, which requires $P_{ji} = h(R_j \| \text{ID}_i \| N_{\text{gs}})$, derivable only from $R_j = \text{PUF}_j(C_j)$ (unclonability). (2)~Symmetrically, UAV$_i$ is authenticated via $Q_j$. (3)~The XOR masks $\text{Mask}_{ij} = P_{ij} \oplus P_{ji}$ are information-theoretically secure one-time pads. \hfill$\square$

\begin{theorem}[MITM Resistance]
\label{thm:mitm}
The protocol resists man-in-the-middle attacks.
\end{theorem}
\emph{Proof:} (1)~All messages are MAC-protected: $\alpha_1$, $\beta_1$, $\gamma_1$, $\delta_1$ in Phase~2 and $\eta_1$, $\eta_2$, $\eta_3$ in Phase~3. Modification is detected via MAC verification failure. (2)~Encrypted puzzles $Q_i$, $Q_j$ cannot be decrypted or re-encrypted without PUF-derived secrets $P_{ij}$, $P_{ji}$. (3)~The PUF response $R_i$ is transmitted only in masked form ($R_i \oplus h(N_2)$), preventing extraction. \hfill$\square$

\begin{theorem}[Physical Capture Resistance]
\label{thm:capture}
Capture of UAV$_i$ does not compromise other UAVs or past sessions.
\end{theorem}
\emph{Proof:} (1)~NVM contains only $\text{TID}_i$ (rotated after each session), $\tau_i$ (useless without PUF to regenerate $R_i$), and masks $\text{Mask}_{ij}$ (require $R_j$ from other PUFs to extract $P_{ji}$). (2)~No raw PUF responses are stored. (3)~Invasive probing to extract the PUF physically destroys it (tamper evidence). (4)~Session key $\text{SK}_{ij} = h(n_i \| n_j \| n_i' \| R_i \| R_j)$ uses ephemeral nonces; past keys cannot be reconstructed. With optional ECDH, perfect forward secrecy is achieved. \hfill$\square$

\section{Discussion}
\label{sec:discussion}

\textbf{Platform considerations:} Our x86-64 results provide accurate \emph{relative} comparisons. On ARM Cortex-M4, SHA3 would degrade 2--20$\times$; with FPGA/ASIC acceleration, hash timing becomes negligible. Real 802.11 MAC overhead (1--10\,ms/frame) would affect all protocols equally.

\textbf{Simulation vs.\ theory:} OMNeT++ measures 175~B (Phase~2) + 104~B (Phase~3) vs.\ theoretical 210 + 196~B, due to simplified credential packaging. Timing impact: $<$0.05\,ms at 6\,Mbps.

\textbf{Limitations:} Fixed UAV set (dynamic join/leave needs Phase~1 extension); 12 CRPs limit sessions before re-enrollment; single-GS design needs extension for multi-GS deployments.

\section{Conclusion}
\label{sec:conclusion}

We presented a four-phase PUF-based authentication protocol for UAV swarm networks, combining PUF hardware root-of-trust with both UAV--GS and direct peer-to-peer authentication in a unified framework. The complete protocol was implemented and evaluated in OMNeT++ 6.3 using a realistic 10-UAV stadium surveillance scenario with dual hash modes. Key findings:

\begin{itemize}[leftmargin=*,nosep]
    \item \textbf{Phase~2 (UAV--GS):} 0.672\,ms (SHA3) / 7.368\,ms (SPONGENT)---10--22$\times$ faster than RSA/ECC alternatives
    \item \textbf{Phase~3 (peer):} 0.476\,ms (SHA3) / 14.535\,ms (SPONGENT) per pair, with 100\% success across all 45 full-mesh pairs
    \item \textbf{Complete swarm:} 28.1\,ms (SHA3) / 727.8\,ms (SPONGENT software) for full 10-UAV mutual authentication
    \item \textbf{Overhead:} 279 bytes/pair (simulation); sub-1\,KB storage per UAV
    \item \textbf{Hardware:} SPONGENT on FPGA (2,190 GE) achieves 33\,ms total swarm authentication---near-identical to SHA3 with 5$\times$ less area and power
    \item \textbf{Security:} Mutual authentication, clone resistance, MITM/replay resistance, no key storage, physical capture resistance---all proven via formal theorems
\end{itemize}

The 2,225$\times$ SHA3-to-SPONGENT software performance gap collapses to 2--5$\times$ on hardware, confirming SPONGENT's suitability as the optimal hash function for FPGA/ASIC-accelerated UAV authentication. All results were obtained on an x86-64 laptop; real deployment on low-power ARM would be 2--20$\times$ slower in software, while FPGA/ASIC acceleration would be 100--400$\times$ faster for SPONGENT.

Future work includes FPGA prototyping on Xilinx Artix-7, MAVLink 2.0 integration for real UAV deployment, adversarial evaluation (jamming, Sybil attacks), large-scale 50--100 UAV simulation, formal ProVerif/Tamarin verification, and post-quantum security assessment.
