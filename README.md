# PUF-Based UAV Swarm Authentication

An OMNeT++ 6.3 implementation of the four-phase PUF-based authentication protocol
specified in [`revised_theory/paper.tex`](revised_theory/paper.tex).

- `src/` — the implementation (crypto suites, PUF models, fuzzy extractor, protocol, nodes)
- `tests/` — unit tests and known-answer tests; the fast development gate
- `simulations/` — network, scenarios, and raw results
- `scripts/` — build, run, export, analyse
- `revised_theory/` — the protocol specification
- `docs/spec-deviations.md` — where the implementation departs from the paper, and why
- `old_theory/`, `old_implementation/` — archived earlier work, frozen
- `REPORT.md`, `report2.md` — the audit that motivated this rewrite

## Environment

OMNeT++ bundles its own Python virtualenv via `setenv`, which conflicts with a
project venv. The analysis scripts use only the standard library, so no venv is
needed:

```bash
cd ~/UAV-OMNET++
source ~/omnetpp-6.3.0/setenv > /dev/null
export PATH="$HOME/omnetpp-6.3.0/bin:$PATH"
which opp_makemake            # should resolve under omnetpp-6.3.0/bin
```

## Build and test

```bash
scripts/build_omnet_project.sh    # always use this, never bare `make`
bash tests/run_tests.sh           # all unit + known-answer tests (~2 min)
bash tests/run_tests.sh bch       # or one suite by substring
```

`src/Makefile` is generated by `opp_makemake` with a static object list and is
git-ignored, so adding or removing a source file requires re-running the build
script. Extra flags belong in `src/makefrag`, which survives regeneration.

Tests are self-registering: each declares its dependencies in a
`// DEPS: <paths relative to src/>` comment line, so adding a test needs no edit
to the runner.

## Run experiments

```bash
python3 scripts/run_experiments.py --skip-build --runs 8 \
        --configs StadiumSHA3 StadiumSPONGENT HighNoise
python3 scripts/analyze_results.py
```

`--clean` archives existing results rather than deleting them. Configurations are
in `simulations/omnetpp.ini`; `repeat = 30` with `seed-set = ${repetition}` is the
default, so every reported mean can carry a confidence interval.

Same-platform PKI baselines:

```bash
g++ -std=c++17 -O2 -I src -I . tests/bench_pki_baseline.cc \
    src/core/*.cc src/crypto/PrimitiveCounters.cc src/crypto/OsslCommon.cc \
    src/crypto/Sha3Suite.cc src/crypto/Drbg.cc src/crypto/X25519.cc \
    -lcrypto -o /tmp/bench_pki && /tmp/bench_pki > simulations/results/omnet_pki_baseline.csv
```

## Design notes

**Two crypto profiles**, selected by the `suite` parameter:

| | `sha3` (software) | `spongent` (constrained hardware) |
|---|---|---|
| hash | SHA3-256 → 160 bits | SPONGENT-160/160/16 |
| MAC | HMAC-SHA3-256 | prefix keyed sponge (KMAC construction) |
| KDF | HKDF | one-pass sponge |
| AEAD | ChaCha20-Poly1305 | Ascon-128a |
| key exchange | X25519 | X25519 |
| hash/MAC level | 128-bit | 80-bit (capacity 160) |

HMAC is undefined over SPONGENT — its rate is 2 bytes, smaller than the key — so
that profile uses the standard keyed-sponge construction instead. Its 80-bit level
is stated explicitly rather than implied.

**No stored secret on the device.** Enrollment distils a stable master key from
the PUF with a fuzzy extractor; the drone keeps only its identity, its challenge,
and the *public* helper data, and regenerates the key on demand. The raw PUF
response never leaves the device.

**Fail closed.** A fuzzy extractor that cannot decode returns no key rather than
an uncorrected value; AEAD authentication failure aborts the handshake; a
low-order Diffie-Hellman point is rejected rather than yielding a zero secret.

**Fuzzy-extractor profiles** (`feProfile`): `bch255-131-18` (default, 4 blocks,
FRR ≈1.2e-3 at 3% BER), `bch255-91-25` (≈4e-7), `rep3-bch255-131-18` (<1e-15 at
3× PUF cost). Response blocks are 255 bits because a code-offset sketch leaks
n−k = 124 bits per block, so a 128-bit block would contribute almost nothing.

**Statistics.** The unit of replication is the run, not the CSV row: rows within a
run share a PRNG stream and a scheduling epoch. `scripts/stats_util.py` takes
per-run means and then a t-interval across runs, and refuses to emit an interval
from fewer than three runs. Success rates carry a Wilson interval, and with no
observed failures the rule-of-three bound is reported — "80 of 80" reads as
"failure probability ≤ 3.75%".

## Verification status

Primitives report what has and has not been checked, via
`Spongent160::verificationStatus()` and `asconVerificationStatus()`:

- **Ascon-128a** — all 1089 vectors of the official LWC known-answer-test file.
- **SPONGENT-160** — byte-exact against the designers' reference implementation
  and the published `"Sponge + Present = Spongent"` vector. No official KAT file
  exists for SPONGENT, and this is not claimed to be one.
- **SHA3 / HMAC / HKDF / ChaCha20-Poly1305 / X25519** — NIST and RFC vectors
  (FIPS 202, RFC 5869, RFC 8439, RFC 7748 §6.1).
- **BCH(255,131,18)** — `deg(g) = 124`, `g(x) | x²⁵⁵+1`, exact correction across
  all 18,000 trials at weights 1–18, and declared failure beyond the radius.
- Neither vendored primitive has had timing or side-channel analysis.

## Status

Implemented and passing: crypto suites, PUF models, fuzzy extractor, the full
four-phase protocol, simulation wiring, results pipeline with confidence
intervals, and same-platform PKI baselines. 9 unit suites, 432k checks.

Not yet implemented: the `AttackerNode` module (the medium supports eavesdrop and
tamper modes, and the attack configurations exist, but the active attacker and the
legacy control arm are not built), the ProVerif/Tamarin model, and the INET
802.11 experiment.
